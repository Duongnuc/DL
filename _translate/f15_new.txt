    """Một khối residual (residual block) — đơn vị xây dựng cơ bản của ResMLP.
    Mỗi ResBlock thực hiện biến đổi 2 tầng rồi cộng kết quả với đầu vào gốc
    (skip connection). Đây là cơ chế cốt lõi giúp ResMLP vượt trội so với
    MLP thông thường.
    Luồng dữ liệu chi tiết (forward pass):
    ───────────────────────────────────────
    Đầu vào x (vector d chiều)
      │
      ├──── lưu bản sao x ──────────────────────────────────┐
      ↓                                                      │
    FC₁(d→d): phép biến đổi tuyến tính = W₁·x + b₁          │
      ↓       (học cách tổ hợp lại các đặc trưng)            │
    BN₁(d): chuẩn hóa batch → ổn định phân phối giá trị     │
    ReLU: max(0, val) → tạo tính phi tuyến                   │
      ↓   (không có phi tuyến, 2 tầng FC = 1 tầng FC)        │
    Dropout(p): tắt ngẫu nhiên p% nơ-ron → chống overfitting │
    FC₂(d→d): biến đổi tuyến tính lần 2 = W₂·h + b₂         │
      ↓       (tinh chỉnh thêm các đặc trưng)                │
    BN₂(d): chuẩn hóa lần nữa trước khi cộng                │
    ╔══════════════════════════════════════╗                  │
    ║  CỘNG element-wise: h + x            ║ ←───────────────┘
    ║  (cộng từng phần tử tương ứng)       ║
    ╚══════════════════════════════════════╝
      ↓
    ReLU: kích hoạt phi tuyến lần cuối
    Đầu ra (vector d chiều, cùng kích thước đầu vào)
    Tại sao có 2 tầng FC mà không phải 1?
    - 1 tầng FC + skip = phép biến đổi tuyến tính cộng với input = vẫn gần
      tuyến tính, khả năng biểu diễn hạn chế.
    - 2 tầng FC + ReLU ở giữa = phép biến đổi PHI TUYẾN phức tạp hơn, có
      thể xấp xỉ nhiều hàm số hơn (theo Universal Approximation Theorem).
    Tham số khởi tạo:
    ─────────────────
        d       (int):   Số chiều của vector đầu vào VÀ đầu ra. Phải bằng
                         nhau để phép cộng skip connection hợp lệ (cộng 2
                         vector cùng kích thước). Thường 96-224.
        dropout (float): Tỷ lệ nơ-ron bị tắt ngẫu nhiên mỗi lần forward,
                         ví dụ 0.1 = tắt 10%. Chỉ hoạt động khi train,
                         khi đánh giá (eval) thì tất cả nơ-ron đều bật.
        # --- Tầng 1: biến đổi tuyến tính đầu tiên ---
        # FC₁ nhận vector d chiều, xuất vector d chiều.
        # Ma trận trọng số W₁ có kích thước d×d, tức d² tham số cần học.
        # Ví dụ d=160: 160×160 = 25.600 tham số chỉ riêng tầng này.
        # BatchNorm chuẩn hóa output của FC₁ về trung bình ≈ 0, độ lệch
        # chuẩn ≈ 1 TRONG MỖI BATCH. Lý do: nếu giá trị quá lớn/nhỏ,
        # ReLU sẽ bão hòa (toàn 0 hoặc toàn dương lớn) → học kém.
        # BN cũng có tác dụng regularization nhẹ vì mỗi batch có thống kê
        # khác nhau → thêm nhiễu → giảm overfitting.
        # Hàm kích hoạt đơn giản nhất và phổ biến nhất. Lý do chọn ReLU:
        # - Tính toán cực nhanh (chỉ so sánh với 0)
        # - Gradient = 1 khi x > 0 → không bị vanishing gradient ở nửa dương
        # - Đủ tốt cho dữ liệu bảng (không cần hàm phức tạp hơn như GELU)
        # Dropout: mỗi lần forward, ngẫu nhiên chọn p% nơ-ron và đặt = 0.
        # Tại sao? Buộc mạng KHÔNG phụ thuộc vào bất kỳ nơ-ron đơn lẻ nào.
        # Giống như dạy một nhóm sinh viên: nếu mỗi buổi học bạn ngẫu nhiên
        # vắng 10% sinh viên, tất cả đều phải tự biết làm thay → nhóm mạnh
        # hơn so với nhóm mà chỉ 1-2 người giỏi "gánh team".
        # --- Tầng 2: biến đổi tuyến tính thứ hai ---
        # Tầng này tinh chỉnh thêm kết quả sau khi ReLU đã tạo phi tuyến.
        # Output sẽ được cộng trực tiếp với input gốc (skip connection),
        # nên kích thước phải giữ nguyên d→d.
        # BN₂ chuẩn hóa lần nữa TRƯỚC khi cộng với x gốc.
        # Lý do: nếu output FC₂ có giá trị rất lớn so với x, phép cộng
        # sẽ bị "lấn át" bởi 1 bên → mất ý nghĩa skip connection.
        # BN₂ giữ giá trị ở cùng "quy mô" (scale) với x → phép cộng
        # cân bằng hơn.
        # --- Nhánh biến đổi: x đi qua 2 tầng FC để tạo "phần dư" h ---
        # Tầng 1: FC₁ → BN₁ → ReLU → Dropout
        # Thứ tự này (Linear→BN→Activation→Dropout) là quy ước phổ biến
        # trong deep learning, gọi là "pre-activation" pattern.
        # Tầng 2: FC₂ → BN₂ (KHÔNG có ReLU ở đây, vì ReLU sẽ áp dụng
        # SAU phép cộng skip connection — nếu ReLU ở đây + ReLU ở sau
        # = 2 lần ReLU liên tiếp, vô ích vì ReLU(ReLU(x)) = ReLU(x))
        # --- Skip connection: cộng đầu vào gốc x với phần dư h ---
        # Đây là dòng code quan trọng nhất trong toàn bộ file!
        # x + h: cộng element-wise, bắt buộc x và h cùng kích thước (d chiều).
        # ReLU cuối cùng kích hoạt tổng. Kết quả có cùng kích thước d
        # → có thể tiếp tục đưa vào ResBlock tiếp theo.
    """Residual MLP — mô hình deep learning chính cho dữ liệu dạng bảng.
    Mô hình ghép nối 3 phần: Input Block → N ResBlock → Head, tạo thành
    một "đường ống" xử lý dữ liệu từ thô đến dự đoán cuối cùng.
    Luồng dữ liệu tổng thể (forward pass):
    ────────────────────────────────────────
    Đầu vào: vector in_dim chiều (mỗi chiều = 1 đặc trưng của dữ liệu)
    [Input Block] FC(in_dim→d) → BN → ReLU → Dropout
      ↓  Mục đích: "nâng" kích thước từ in_dim lên d để tương thích
      ↓  với các ResBlock phía sau (ResBlock yêu cầu input d chiều)
    [ResBlock_1] 2×FC + skip connection (d→d)
    [ResBlock_2] 2×FC + skip connection (d→d)
    ... (tổng cộng N ResBlock)
    [ResBlock_N] 2×FC + skip connection (d→d)
    [Head] FC(d→1): nén thành 1 số = giá trị dự đoán (hồi quy)
    Đầu ra: 1 số thực (scalar) cho mỗi mẫu dữ liệu trong batch
        in_dim  (int):   Số đặc trưng đầu vào. Ví dụ: dữ liệu có 30 cột
                         đặc trưng → in_dim = 30. Con số này phụ thuộc vào
                         bước tiền xử lý dữ liệu, KHÔNG phải siêu tham số
                         cần tuning.
        d       (int):   Chiều (width) của tất cả tầng ẩn bên trong mô hình.
                         Càng lớn = mạng càng "rộng" = nhiều tham số hơn =
                         có thể học pattern phức tạp hơn, nhưng cũng dễ
                         overfitting và chậm hơn. Phạm vi tìm kiếm: 96-224.
        blocks  (int):   Số ResBlock xếp chồng. Càng nhiều = mạng càng "sâu"
                         = có thể học biểu diễn trừu tượng hơn. Nhờ skip
                         connection, thêm block không gây hại. Phạm vi: 2-4.
        dropout (float): Tỷ lệ nơ-ron bị tắt ngẫu nhiên, ví dụ 0.1 = 10%.
                         Giá trị lớn hơn = regularization mạnh hơn = ít
                         overfitting nhưng khó hội tụ. Phạm vi: 0.05-0.25.
        # --- Input Block: chuyển đổi kích thước từ in_dim sang d ---
        # Tại sao cần block này? Vì in_dim (số đặc trưng gốc, ví dụ 30)
        # thường khác d (chiều tầng ẩn, ví dụ 160). ResBlock yêu cầu
        # input và output cùng kích thước d (để cộng skip connection).
        # Nên cần FC(in_dim→d) để "nâng chiều" trước khi vào ResBlock.
        # BN + ReLU + Dropout giúp ổn định và regularize ngay từ đầu.
        # --- N ResBlock xếp chồng: trích xuất đặc trưng ngày càng trừu tượng ---
        # nn.Sequential xếp các block nối tiếp: output block 1 → input block 2.
        # Mỗi block giữ nguyên kích thước d → có thể xếp bao nhiêu tùy ý.
        # Số block (2-4) được Optuna tối ưu: quá ít → underfit, quá nhiều →
        # overfitting trên tập dữ liệu nhỏ (vì thêm tham số nhưng không thêm
        # thông tin mới từ dữ liệu).
        # --- Head: tầng dự đoán cuối cùng ---
        # Nén từ d chiều xuống 1 số duy nhất. Đây là bài toán hồi quy
        # (regression), nên KHÔNG có hàm kích hoạt sau FC — đầu ra là
        # số thực bất kỳ (có thể âm, dương, hoặc 0).
        # Nếu là bài phân loại, ta sẽ thêm Sigmoid (2 lớp) hoặc
        # Softmax (nhiều lớp) ở đây, nhưng ở đây ta không cần.
        # Luồng forward rất gọn nhờ nn.Sequential:
        # 1. self.inp(x): Input Block biến x từ in_dim chiều → d chiều
        # 2. self.blocks(...): Chuỗi N ResBlock, mỗi block d→d với skip
        # 3. self.head(...): FC(d→1) cho ra 1 số dự đoán
        # Toàn bộ quá trình diễn ra tự động khi gọi model(x) nhờ PyTorch.
    """Tạo một instance ResMLP từ dictionary siêu tham số.
    Hàm này là "cầu nối" giữa Optuna (trả về dict tham số) và ResMLP
    (nhận các tham số riêng lẻ). Cần ép kiểu int/float vì Optuna có thể
    trả về numpy type không tương thích trực tiếp với PyTorch.

                               - "res_blocks": số ResBlock
                               - "dropout": tỷ lệ dropout
        nn.Module: Instance ResMLP đã khởi tạo, sẵn sàng huấn luyện.
        # ── lr (learning rate - tốc độ học) ──

        # Một dạng regularization: mỗi bước cập nhật, trọng số bị nhân với
        # (1 - wd), kéo chúng về gần 0. Tác dụng: ngăn trọng số quá lớn →
        # mô hình tổng quát hóa tốt hơn trên dữ liệu mới (giảm overfitting).
        # log=True: vì wd cũng phân bố trên thang log.
        # Quá nhỏ (1e-6): gần như không có regularization.
        # Quá lớn (3e-4): trọng số bị ép quá gần 0, mạng mất khả năng học.

        # cần dropout, nhưng cũng không cần quá cao vì mất thông tin.
        # 0.05: chỉ tắt 5% → regularization nhẹ → phù hợp tập lớn.
        # 0.25: tắt 25% → regularization mạnh → phù hợp tập nhỏ, dễ overfit.
        # ── res_d (chiều tầng ẩn - hidden dimension) ──

        # ResBlock đều dùng chung kích thước này.

        #          (Tensor Core hoạt động hiệu quả nhất với kích thước bội 16).
        # 96:  mạng hẹp, ít tham số (~50K), nhanh nhưng có thể underfit.
        # 224: mạng rộng, nhiều tham số (~300K), mạnh nhưng chậm và dễ overfit.
        # ── res_blocks (số ResBlock xếp chồng) ──
        # Quyết định "chiều sâu" (depth) của mạng.
        # 2: mạng nông → 4 tầng FC (2 block × 2 tầng) + input block + head
        #    = tổng cộng 6 tầng biến đổi. Phù hợp dữ liệu đơn giản.
        # 4: mạng sâu → 8 tầng FC + input + head = 10 tầng biến đổi.
        #    Cần nhiều dữ liệu hơn để train hiệu quả.
        # Nhờ skip connection, 4 block KHÔNG tệ hơn 2 block (worst case:
        # 2 block thừa sẽ trở thành identity → mạng 4 block ≈ mạng 2 block).
    """Mô hình hồi quy GRU theo kiến trúc sequence-to-sequence (seq2seq).
    Lớp này đóng gói toàn bộ kiến trúc mạng nơ-ron GRU dùng để dự đoán giá trị
    co ngót tại MỌI bước thời gian trong chuỗi (không chỉ bước cuối).
    Kiến trúc bên trong:
    1. Lớp GRU (nn.GRU):
       - Nhận chuỗi features đầu vào, xử lý tuần tự từng bước thời gian
       - Tại mỗi bước, áp dụng 2 cổng (reset + update) để cập nhật hidden state
       - Có thể xếp chồng nhiều tầng (num_layers > 1) để học biểu diễn phức tạp hơn
       - Khi num_layers > 1: output của tầng dưới là input cho tầng trên,
         dropout được áp dụng GIỮA các tầng (không áp dụng ở tầng cuối)
       - Lớp kết nối đầy đủ (fully connected) chuyển hidden state -> giá trị dự đoán
       - Ánh xạ từ hidden_dim chiều -> 1 chiều (1 giá trị co ngót)
       - Được áp dụng CÙNG MỘT BỘ TRỌNG SỐ cho mọi bước thời gian
         (parameter sharing, giúp giảm overfitting)
    Kích thước dữ liệu (tensor shapes):
    Đầu vào x:
        - batch_size: số chuỗi được xử lý đồng thời trong 1 batch
          Ví dụ: batch_size=16 nghĩa là 16 nhóm mẫu (GID) cùng lúc
        - seq_len:    độ dài chuỗi (số bước thời gian), đã được padding về cùng
                      độ dài trong 1 batch. Ví dụ: 50 ngày đo
        - input_dim:  số features tại mỗi bước thời gian
                      Ví dụ: [tuổi, nhiệt_độ, độ_ẩm, tỷ_lệ_xi_măng, ...] = 8 features
    Trạng thái ẩn (hidden state) sau GRU:
        - hidden_dim: kích thước vector trạng thái ẩn, do người dùng chọn
          Ví dụ: hidden_dim=64 nghĩa là mỗi bước thời gian có vector 64 chiều
                 chứa thông tin "tóm tắt" của toàn bộ quá khứ đến thời điểm đó
    Đầu ra (predictions):
        - Mỗi phần tử là 1 giá trị dự đoán co ngót tại bước thời gian tương ứng
    input_dim  (int):   Số lượng features đầu vào tại mỗi bước thời gian.
                        Được xác định tự động từ dữ liệu huấn luyện.
    hidden_dim (int):   Kích thước hidden state. Giá trị lớn hơn cho phép mô hình
                        học các pattern phức tạp hơn, nhưng tăng thời gian tính toán
                        và nguy cơ overfitting. Thường thử: 32, 48, 64.
    num_layers (int):   Số tầng GRU xếp chồng. 1 tầng thường đủ cho dữ liệu đơn
                        giản; 2 tầng giúp học biểu diễn trừu tượng hơn nhưng chậm hơn.
    dropout    (float): Tỷ lệ dropout (0.0 đến 1.0) GIỮA các tầng GRU.
                        Dropout ngẫu nhiên "tắt" một phần neuron trong quá trình
                        huấn luyện để chống overfitting. Chỉ có tác dụng khi
                        num_layers > 1 (vì dropout áp dụng giữa các tầng, không
                        áp dụng ở tầng cuối cùng).
        # Gọi __init__ của lớp cha nn.Module - bắt buộc để PyTorch quản lý
        # tham số (weights, biases) và hỗ trợ .to(device), .parameters(), v.v.
        # Lớp GRU chính: xử lý chuỗi tuần tự qua các bước thời gian.
        # Tham số:
        #   input_size  = input_dim  : số features đầu vào mỗi bước
        #   hidden_size = hidden_dim : kích thước vector trạng thái ẩn
        #   num_layers  : số tầng GRU xếp chồng (stacked GRU)
        #   dropout     : tỷ lệ dropout giữa các tầng (0 nếu chỉ 1 tầng,
        #                 vì PyTorch yêu cầu dropout=0 khi num_layers=1)
        #   batch_first = True : quy ước đầu vào có shape (batch, seq, feat)
        #                 thay vì (seq, batch, feat). Cách này trực quan hơn
        #                 và phù hợp với cách ta tổ chức dữ liệu.
        # FC Head (Fully Connected Head): lớp tuyến tính ánh xạ
        # hidden state (hidden_dim chiều) -> 1 giá trị dự đoán.
        # Ví dụ: nếu hidden_dim = 64, lớp này có:
        #   - Ma trận trọng số W: shape (1, 64) -> 64 tham số
        #   - Bias b: shape (1) -> 1 tham số
        #   - Tổng: 65 tham số học được
        # Lớp này được áp dụng RIÊNG RẼ cho từng bước thời gian nhưng
        # dùng CÙNG trọng số (weight sharing), giúp mô hình nhất quán
        # và giảm số tham số cần học.
        """Lan truyền xuôi (forward pass) - tính dự đoán từ đầu vào.
        Đây là hàm được PyTorch gọi tự động khi ta viết model(x).
        Nó mô tả CÁCH dữ liệu chảy qua mô hình từ đầu vào đến đầu ra.
            x: Tensor đầu vào, shape (batch_size, seq_len, input_dim).
               Mỗi phần tử x[i, t, :] là vector features của chuỗi thứ i
               tại bước thời gian thứ t.
            Tensor dự đoán, shape (batch_size, seq_len).
            Mỗi phần tử output[i, t] là giá trị co ngót dự đoán của chuỗi
            thứ i tại bước thời gian thứ t.
        # Bước 1: Đưa chuỗi qua GRU
        # self.gru(x) trả về tuple gồm 2 phần:
        #   - hidden: (batch, seq_len, hidden_dim) - trạng thái ẩn TẠI MỌI bước
        #             Đây là "bộ nhớ ngắn hạn" chứa thông tin tích luỹ từ đầu
        #             chuỗi đến bước hiện tại.
        #   - _     : (num_layers, batch, hidden_dim) - trạng thái ẩn cuối cùng
        #             của mỗi tầng GRU. Ta không cần giá trị này nên dùng _.
        # Bước 2: Ánh xạ hidden state -> giá trị dự đoán qua FC head
        #   Lớp Linear áp dụng phép nhân ma trận + bias cho mỗi vector hidden.
        # .squeeze(-1): bỏ chiều cuối cùng (chiều có size=1)
        #   Kết quả: mỗi bước thời gian có đúng 1 giá trị dự đoán.
    """Tạo mô hình GRU từ bộ siêu tham số (hyperparameters) do Optuna đề xuất.
    Hàm này là "cầu nối" giữa Optuna (tìm siêu tham số) và kiến trúc mô hình.
    Mỗi khi Optuna thử một bộ tham số mới, hàm này được gọi để tạo mô hình
    tương ứng, sau đó mô hình được huấn luyện và đánh giá.
        input_dim: Số features đầu vào (được xác định tự động từ dữ liệu).
        params:    Dict chứa siêu tham số do suggest_params() đề xuất.
                   Bắt buộc có: hidden_dim, num_layers, dropout.
        nn.Module: Một instance GRURegressor sẵn sàng huấn luyện.
        hidden_dim=int(params["hidden_dim"]),   # Ép kiểu int vì Optuna có thể trả float
        num_layers=int(params["num_layers"]),    # Số tầng GRU (1 hoặc 2)
        dropout=float(params["dropout"]),        # Tỷ lệ dropout (0.05 đến 0.30)
    """Định nghĩa không gian tìm kiếm siêu tham số (search space) cho Optuna.
    Optuna sẽ gọi hàm này mỗi trial (lần thử) để lấy một bộ tham số mới.
    Mỗi tham số được chọn từ một khoảng giá trị hợp lý, và Optuna sẽ dần
    tập trung vào vùng cho kết quả tốt nhất (Bayesian optimization).
    Không gian tìm kiếm:
        Kích thước hidden state. Chọn từ 3 giá trị cố định thay vì dải liên tục
        để giảm không gian tìm kiếm. 32 = nhẹ nhất, 64 = mạnh nhất.
        Với dữ liệu co ngót (pattern không quá phức tạp), 32-64 thường đủ.

        Số tầng GRU xếp chồng. 1 tầng = đơn giản, nhanh. 2 tầng = học biểu
        diễn sâu hơn nhưng chậm hơn và dễ overfitting hơn.
        Không thử 3+ tầng vì dữ liệu co ngót thường không đủ lớn/phức tạp.
    dropout (float: 0.05 đến 0.30):
        Tỷ lệ neuron bị "tắt" ngẫu nhiên khi huấn luyện. Giúp chống overfitting.

        bố theo logarit (1e-4 và 1e-3 "cách nhau" tương đương 1e-3 và 1e-2).
    wd (float: 1e-7 đến 1e-3, log scale):
        Weight decay - hệ số phạt L2 regularization. Ngăn trọng số quá lớn,
        giúp mô hình tổng quát hoá tốt hơn. Log scale vì lý do tương tự lr.
        trial: Đối tượng Optuna trial, cung cấp phương thức suggest_*
               để chọn giá trị tham số.
        dict: Bộ siêu tham số cho 1 lần thử nghiệm.
    """Mô hình hồi quy LSTM theo kiến trúc sequence-to-sequence (seq2seq).
    Lớp này đóng gói toàn bộ kiến trúc mạng nơ-ron LSTM dùng để dự đoán
    giá trị co ngót tại MỌI bước thời gian trong chuỗi (không chỉ bước cuối).
    1. Lớp LSTM (nn.LSTM):
       - Tại mỗi bước, áp dụng 3 cổng (forget + input + output) và cập nhật
         cell state để quản lý bộ nhớ dài hạn
       - Có thể xếp chồng nhiều tầng (num_layers > 1) để học biểu diễn sâu hơn
       - Khi num_layers > 1: output tầng dưới là input tầng trên, dropout được

       - Ánh xạ: hidden_dim chiều -> 1 chiều (1 giá trị scalar)

       - GRU trả về: (output, h_n) - chỉ có hidden state
       - LSTM trả về: (output, (h_n, c_n)) - có CẢ hidden state VÀ cell state
       - Tuy nhiên, phần FC head giống hệt: chỉ dùng output (hidden state tại

                        thước). Giá trị lớn hơn -> mô hình mạnh hơn nhưng chậm
                        hơn và dễ overfitting. Thường thử: 32, 48, 64.
    num_layers (int):   Số tầng LSTM xếp chồng. 1 tầng thường đủ cho bài toán
                        đơn giản; 2 tầng giúp học biểu diễn trừu tượng hơn.
    dropout    (float): Tỷ lệ dropout (0.0 đến 1.0) GIỮA các tầng LSTM.
                        Ngẫu nhiên "tắt" neuron khi huấn luyện để chống overfitting.
                        Chỉ có tác dụng khi num_layers > 1 (PyTorch không áp dụng
                        dropout ở tầng cuối cùng).

        # Lớp LSTM chính: xử lý chuỗi tuần tự qua các bước thời gian.
        # KHÁC BIỆT với GRU (buoc_07):
        #   - LSTM duy trì CẢ hidden state (h) VÀ cell state (c) qua mỗi bước
        #   - Có 3 cổng thay vì 2 -> nhiều tham số hơn khoảng 33%
        #   - Cùng hidden_dim=64: GRU có ~3*64*64 = 12,288 tham số cổng,
        #     LSTM có ~4*64*64 = 16,384 tham số cổng (4 ma trận thay vì 3)
        #   hidden_size = hidden_dim : kích thước hidden state VÀ cell state
        #   num_layers  : số tầng LSTM xếp chồng (stacked LSTM)
        #   dropout     : tỷ lệ dropout giữa các tầng (0 nếu chỉ 1 tầng)

        #                 (seq, batch, feat). Cách này trực quan hơn.
        # FC Head: lớp tuyến tính ánh xạ hidden state -> 1 giá trị dự đoán.
        # Hoàn toàn giống với GRU (buoc_07): cùng cấu trúc Linear(hidden_dim, 1)
        # vì cả GRU và LSTM đều xuất hidden state cùng kích thước.

        - LSTM: self.lstm(x) trả về (output, (h_n, c_n))

        - Tuy nhiên, ta chỉ dùng output (hidden state tại mọi bước) nên
          code trông gần giống nhau.

        # self.lstm(x) trả về tuple gồm 2 phần:

    """Tạo mô hình LSTM từ bộ siêu tham số (hyperparameters) do Optuna đề xuất.

    để huấn luyện và đánh giá.

        num_layers=int(params["num_layers"]),    # Số tầng LSTM (1 hoặc 2)

    LƯU Ý: Search space này GIỐNG HỆT với GRU (buoc_07). Điều này có CHỦ ĐÍCH:
    - Cùng search space -> so sánh công bằng giữa 2 kiến trúc
    - Sự khác biệt trong kết quả phản ánh khác biệt KIẾN TRÚC, không phải
      khác biệt siêu tham số
        Kích thước hidden state VÀ cell state (cả hai cùng kích thước trong LSTM).
