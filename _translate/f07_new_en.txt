# PART 3/4 - MODEL ARCHITECTURE + SEARCH SPACE (merged from buoc_07_gru.py)
Step 07 - GRU (Gated Recurrent Unit) model for predicting shrinkage time series.
WHAT IS GRU?
GRU (short for Gated Recurrent Unit) is
a recurrent neural network (RNN) architecture proposed
by Cho et al. in 2014. It is a simplified version of LSTM, designed
to address the "long-term memory loss" (vanishing gradient) problem that traditional
RNNs suffer from, but with fewer parameters than LSTM.
Core idea: when processing data sequences over time (e.g. the shrinkage level
of concrete over successive days), the model needs to "remember" important information from the
past and "forget" what is no longer relevant. GRU does this through
two special gates.
DETAILED ARCHITECTURE - GRU'S TWO GATES
At each time step t, GRU receives:
  - x_t  : the feature vector at time t
  - h_{t-1}: the hidden state from the previous step
And computes through 2 gates:
1) RESET GATE - denoted r_t:
   Formula: r_t = sigmoid(W_r * [h_{t-1}, x_t])
   - Decides "what percentage" of past information (h_{t-1}) will be DISCARDED
     when computing the new hidden state.
   - If r_t is near 0: the model almost "forgets everything" from the past, relying only on the
     current data x_t -> useful when encountering a turning point, a sudden change.
   - If r_t is near 1: the model retains most of the past -> useful when a trend
     is still continuing steadily.
   - Shrinkage example: if currently in the initial drying stage (rapid change),
     the reset gate may "open" to react quickly to new data.
2) UPDATE GATE - denoted z_t:
   Formula: z_t = sigmoid(W_z * [h_{t-1}, x_t])
   - Decides "what percentage" of the newly computed hidden state will REPLACE
     the old hidden state.
   - If z_t is near 1: KEEPS the old state h_{t-1} unchanged, ignoring new information
     -> acts like a "shortcut" (skip connection), helping combat vanishing gradient.
   - If z_t is near 0: FULLY REPLACES with the new state
     -> the model actively updates when there is important new information.
   - Shrinkage example: in a stable stage (slow shrinkage), the update gate tends to be
     near 1 to "keep" the state, no need to update much.
The new hidden state is computed as:
   h_tilde = tanh(W * [r_t * h_{t-1}, x_t])   <-- "candidate" state
   h_t     = z_t * h_{t-1} + (1 - z_t) * h_tilde  <-- combining old + new
Important note: GRU does NOT have a separate cell state (unlike LSTM). All
memory is packed into the hidden state h_t. This makes GRU simpler
but also limits its ability to store extremely long-term information.
WHY USE GRU FOR SHRINKAGE TIME SERIES?
Concrete shrinkage data has the following characteristics:
  - It is a time series: measurements are recorded in time order
  - It has a trend: shrinkage typically increases then gradually stabilizes over time
  - It is context-dependent: today's shrinkage value depends on the previous day
  - Variable length: each sample group (GID) has a different number of measurements
GRU is well suited because:
  a) It processes sequential data naturally (one time step at a time)
  b) The update gate helps "remember" the long-term shrinkage trend
  c) The reset gate helps "adapt" when there is a sudden change
  d) It is faster than LSTM, saving training time
  e) It has fewer parameters than LSTM, so it overfits less on small data
SEQUENCE-TO-SEQUENCE (SEQ2SEQ) PREDICTION ARCHITECTURE
Instead of predicting only 1 final value (many-to-one), this model predicts
a value at EVERY time step (many-to-many, i.e. seq2seq):
  Input:  [x_1, x_2, ..., x_T]    (T steps, each step has D features)
  Output: [y_1, y_2, ..., y_T]    (T predicted shrinkage values)
How it works:
  Step 1: GRU processes x_1 -> produces h_1
  Step 2: GRU processes x_2 (along with h_1) -> produces h_2
  Step T: GRU processes x_T (along with h_{T-1}) -> produces h_T
  Then, each h_t is passed through a Linear layer (FC head):
Reason for using seq2seq: every shrinkage measurement point matters, not just the last one.
The model learns to predict the ENTIRE shrinkage curve, not just the final value.
COMPARISON WITH LSTM (Long Short-Term Memory)
  Number of gates:       2 (reset + update)          3 (forget + input + output)
  Separate cell state:   NO                          YES (dedicated long-term memory)
  Number of parameters:  Fewer (~25% fewer than LSTM)  More
  Training speed:        Faster                       Slower
  Short sequences (<100): Usually good enough          Can be overly complex
  Long sequences (>500):  May be worse                 Usually better
  Small data:            Less overfitting               More prone to overfitting
With shrinkage data (typically short-to-medium sequences, not very large data),
GRU is usually a good and more efficient choice than LSTM.
HOW IT'S OPTIMIZED: OPTUNA + MASKED MSE + LOG1P TARGET
   - Automatically searches for the best hyperparameter set (hidden_dim, num_layers, etc.)
   - Instead of trying every combination (grid search), Optuna uses a smart algorithm
     (TPE - Tree-structured Parzen Estimator) to "guess" promising parameter regions
   - Saves a lot of time compared to grid search
2) Masked MSE (Mean Squared Error with a mask):
   - Because sequences have different lengths, we must pad shorter sequences
     with a fake value (usually 0) to form a uniform batch
   - The mask marks which points are REAL and which are FAKE (due to padding)
   - When computing the loss, only compute MSE on the REAL points, skipping the padding points
   - Without a mask: the model would "learn" to predict 0 for padding positions,
     biasing the result
3) Log1p target (logarithmic transform):
   - The shrinkage value has a right-skewed distribution: many small values, few
     large values
   - log1p(y) = log(1 + y) "compresses" the distribution, making it more symmetric
   - The model learns more easily when the target has a near-Gaussian distribution
   - When predicting, use expm1() to convert back: expm1(y_hat) = exp(y_hat) - 1
ADVANTAGES OF GRU
  + Simple, few parameters -> fast training, less overfitting
  + Good performance for short-to-medium sequences
  + Easier to implement and debug than LSTM
  + Good gradient flow thanks to the update gate (similar to a skip connection)
  + Suitable when data is limited (less prone to overfitting)
DISADVANTAGES OF GRU
  - No separate cell state -> hard to remember information very far back in long sequences
  - For very long sequences (>500 steps), LSTM is usually superior
  - Less flexible than LSTM in controlling information flow
  - Not always better than LSTM; both should be tried for comparison
