# PART 3/4 - MODEL ARCHITECTURE + SEARCH SPACE (merged from buoc_08_lstm.py)
Step 08 - LSTM (Long Short-Term Memory) model for predicting shrinkage time series.
WHAT IS LSTM?
LSTM (short for Long Short-Term Memory) is
a recurrent neural network (RNN) architecture proposed by Hochreiter & Schmidhuber
in 1997. It is the classic and most popular RNN architecture, specifically designed
to address the "long-term memory loss" (vanishing gradient) problem that traditional
RNNs suffer from when processing long sequences.
Core idea: LSTM has its own dedicated "highway" called the cell state, allowing
important information to "flow" throughout the sequence without decaying. Three special
gates control adding, removing, or reading information from this cell state.
DETAILED ARCHITECTURE - THREE GATES AND THE CELL STATE
At each time step t, LSTM receives:
  - x_t      : the feature vector at time t
  - h_{t-1}  : the hidden state from the previous step
  - C_{t-1}  : the cell state from the previous step
And computes through 3 gates + 1 cell state:
1) FORGET GATE - denoted f_t:
   Formula: f_t = sigmoid(W_f * [h_{t-1}, x_t] + b_f)
   - Decides "what percentage" of the information in the old cell state will be ERASED.
   - Sigmoid gives a value from 0 to 1:
     * f_t near 0: ERASES almost all old information -> "forgets" the past
     * f_t near 1: KEEPS almost all old information -> "remembers" the past
   - Shrinkage example: if the environmental conditions change suddenly (switching from
     drying to water immersion), the forget gate can "erase" old information that is no longer
     relevant.
2) INPUT GATE - denoted i_t:
   Formula: i_t = sigmoid(W_i * [h_{t-1}, x_t] + b_i)
   Candidate:  C_tilde = tanh(W_C * [h_{t-1}, x_t] + b_C)
   - The input gate has 2 parts:
     a) i_t: decides "what percentage" of NEW information will be WRITTEN IN
     b) C_tilde: a "candidate" vector containing potential new information (value from
        -1 to 1 thanks to tanh)
   - Combined: i_t * C_tilde = the portion of new information actually added
   - Shrinkage example: when an important new measurement comes in (e.g. a sudden spike in shrinkage),
     the input gate "opens" to record this information into long-term memory.
3) CELL STATE UPDATE:
   Formula: C_t = f_t * C_{t-1} + i_t * C_tilde
   - This is the MOST IMPORTANT step, combining "forgetting" and "remembering":
     * f_t * C_{t-1}: the portion of old information that is KEPT (after forget gate filtering)
     * i_t * C_tilde: the portion of new information that is ADDED (after input gate filtering)
   - The cell state acts like a "conveyor belt": information can
     flow throughout the sequence almost unchanged if the forget gate = 1 and the
     input gate = 0. This is exactly how LSTM solves the vanishing gradient problem!
4) OUTPUT GATE - denoted o_t:
   Formula: o_t = sigmoid(W_o * [h_{t-1}, x_t] + b_o)
   - Decides "what percentage" of the information from the cell state will be OUTPUT
     as the hidden state (to use for prediction and the next step).
   - tanh(C_t) squashes the cell state into the range [-1, 1]
   - o_t selects which part gets output
   - Shrinkage example: the output gate decides which information in long-term memory
     is useful for predicting shrinkage at the current time.
WHY DOES LSTM HAVE A CELL STATE? - THE CORE DIFFERENCE FROM GRU
The cell state is a SEPARATE "long-term memory", detached from the hidden state:
  - Hidden state (h_t): "working memory" - contains information needed RIGHT NOW
    to make a prediction and pass to the next step.
  - Cell state (C_t): "long-term memory" - stores information that may be needed in the
    FAR FUTURE. This information is protected by the gates, not continuously
    transformed through matrix multiplications like the hidden state.
Why is separation needed?
  a) The hidden state is transformed heavily at each step (sigmoid, tanh) -> information
     decays quickly. If only the hidden state were used (like GRU), it would be hard to remember information
     from 100+ steps ago.
  b) The cell state has an ADDITIVE mechanism: C_t = f * C_{t-1} + i * C_tilde
     Addition lets the gradient flow backward easily (not multiplied repeatedly),
     so information from very far back can still influence the present.
  c) Three separate gates allow fine-grained control: what to forget, what to remember,
     what to output - each has its own "controller".
GRU merges the cell state and hidden state into ONE (only h_t), simpler but
less flexible in managing long-term vs. short-term memory.
DETAILED COMPARISON WITH GRU (Gated Recurrent Unit)
  Number of gates:       3 (forget+input+output)      2 (reset+update)
  Separate cell state:   YES (long-term memory)       NO (only a hidden state)
  Number of parameters:  More (~33% more)              Fewer
  Training speed:        Slower                        Faster
  Memory (RAM):          More expensive                More economical
  Short sequences (<100): Can be overly complex         Usually good enough
  Long sequences (>500):  Usually better                May be worse
  Memory control:        Finer-grained (3 separate gates) Simpler (2 gates)
  Small data:            More prone to overfitting      Less overfitting
  Research history:      Older, many variants           Newer, fewer variants
When to choose LSTM instead of GRU?
  - Long sequences where information from very far back needs to be remembered
  - Data is large enough to avoid overfitting
  - Fine-grained control between long-term and short-term memory is needed
  - The pattern in the data is complex, with many layers of abstraction
For shrinkage data, the BEST APPROACH is to run both GRU and LSTM then compare results,
because there is no way to know in advance which model is better for a specific dataset.
   - Uses the TPE (Tree-structured Parzen Estimator) algorithm - a form of
     Bayesian optimization - to "guess" promising parameter regions based on
     the results of previous trials
   - Much more efficient than grid search (trying every combination) or
     random search (trying randomly)
   - Because sequences have different lengths (each GID has a different number of measurement days),
     shorter sequences must be padded (with 0) to form a uniform batch
   - The mask is a True/False tensor marking: True = a REAL data point,
     False = a FAKE padding point
   - The loss is computed only on REAL points: MSE = sum((y_pred - y_true)^2 * mask) / sum(mask)
   - Without a mask: the model would learn to "predict 0" for padding, distorting the results
   - The shrinkage value has a right-skewed distribution: many small values, few large values
   - log1p(y) = log(1 + y): "compresses" the value range, making the distribution closer to normal
   - DL models perform better when the target distribution is symmetric, near Gaussian
   - When producing the final prediction: use expm1(y_hat) = exp(y_hat) - 1 to convert back
ADVANTAGES OF LSTM
  + Separate cell state -> remembers information very far back in long sequences
  + Three independent gates -> fine-grained control over information flow
  + Additive mechanism in the cell state -> good gradient flow, less vanishing
  + Long-established architecture, well studied, many improved variants
  + Usually superior for long sequences (>500 steps) or complex patterns
DISADVANTAGES OF LSTM
  - More parameters than GRU (~33%) -> slower to train and infer
  - Uses more memory (RAM/VRAM) since it stores both the hidden state and the cell state
  - More prone to overfitting than GRU when data is limited (due to more parameters)
  - More complex to understand, debug, and tune
  - For short sequences, the cell state advantage is unclear -> GRU may be good enough
  - Sequential training -> cannot take advantage of parallelization
    like a Transformer
